# 仕組みと制約

[README](../README.md) に戻る。

## 候補と固定したテスト

候補は、実装や修正が終わった時点のコードです。検査、レビュー、承認、成果物に同じ版を使えるよう識別します。修正で候補が変わると、新しい候補に対して検査とレビューをやり直します。

| 対象           | 候補                                                   | 検査                                                                                               |
| -------------- | ------------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| 同梱サンプル   | ファイルをコピーし、ハッシュで確認します。             | 開始時に別の場所へコピーした受け入れテストを `node --test` で実行します。                          |
| Git リポジトリ | 専用の worktree で作業し、候補をコミットで固定します。 | 開始時に決めたコマンドと引数を使います。候補が追加・変更したテストも、二つのレビューで確認します。 |

固定した検査は、引数の配列を子プロセスに渡します。時間切れや取り消しではプロセスグループごと停止します。設定については [リポジトリの設定](configuration.md) を参照してください。

## 呼び出しの識別と復旧

工程の結果は Durably に保存します。再開時は、完了済みの工程の結果を読み戻します。候補を変えずに再開する場合は、同じ候補で終わったレビューの結果を使います。

| ID             | 識別するもの                                     |
| -------------- | ------------------------------------------------ |
| `sessionId`    | プロバイダー側の会話。                           |
| `operationKey` | 修正やレビューなど、工程内の一つの作業。         |
| `invocationId` | プロバイダーや検査プログラムに送った一回の依頼。 |
| `attempt.id`   | Durably が工程の処理を試した一回。               |

LLM 呼び出しや固定検査は、開始の記録を保存してから実行し、結果を保存してから工程を完了します。開始の記録だけが残った固定検査は、同じ候補でやり直します。LLM 呼び出しは利用枠をすでに消費した可能性があるため、停止して人の判断を待ちます。確認して送り直す手順は [日々の操作](operations.md) にあります。

## 権限と制約

セットアップや検査はローカルの子プロセスで動くので、信頼できるリポジトリとコマンドを使います。worktree は作業の場所を分けるために使います。

- Codex は実装と修正で `workspace-write`、レビューと見立てで `read-only` を使います。
- Claude Code の実装と修正では、ツールの呼び出し時にパスを検査します。OS レベルの隔離が必要なコードは別の環境で扱います。通常のレビューと見立ては読み取り専用です。Claude の独自レビューコマンドが使えるツールと設定は [見立て、レビュー、修正](review-and-repair.md) にあります。
- 仕様の作成と修正はリポジトリを読み、実行の `spec/spec.md` に書きます。仕様のレビューは読むだけです。
- 同じセッションへの呼び出しは一つずつ送ります。実装と修正でセッションを引き継ぐ条件は [リポジトリの設定](configuration.md) を参照してください。

## fake モードの詳細

`trigger --provider fake` で、LLM を使わずに実装とレビューの流れを試せます。環境変数は、実際に処理を行うワーカーに渡します。すでにワーカーを起動している場合は、別の `HOME` で試せます。

| 環境変数               | 例と動作                                                     |
| ---------------------- | ------------------------------------------------------------ |
| `FAKE_FAIL_FIRST`      | `0` で同梱サンプルの初回の検査を通します。                   |
| `FAKE_REVIEW_SEQUENCE` | `pass` で模擬レビューを通します。                            |
| `FAKE_LATENCY_MS`      | `20000-90000` で各呼び出しを指定範囲のミリ秒だけ待たせます。 |
| `FAKE_USAGE`           | `realistic` で模擬の使用量を記録します。                     |

## ファイルの構成

| 場所                                                     | 担当                                                       |
| -------------------------------------------------------- | ---------------------------------------------------------- |
| [`src/engine/`](../src/engine/)                          | LLM 呼び出し、検査、候補、計測など、対象に依存しない処理。 |
| [`src/factory/`](../src/factory/)                        | 工程の順序、修正の反復、承認と復旧。                       |
| [`src/targets/`](../src/targets/)                        | 同梱サンプルと Git リポジトリの作業方法。                  |
| [`src/cli.ts`](../src/cli.ts) と [`src/ui/`](../src/ui/) | CLI とブラウザからの操作。                                 |

設計を決めた経緯は [ADR](adr/README.md) にあります。

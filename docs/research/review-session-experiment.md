# レビューセッション継続の実CLI検証

2026-11-11。Claude Opus 5.5 / medium、Claude Code 2.1.321、Agent SDK 0.3.321。
factoryの実運用DB・ワーカーは使わず、productionのproviderとrunnerを専用ディレクトリから呼び出した。
使用量・適用単価・CLIの版を [計測JSON](review-session-smoke.json) に保存した。プロンプト、返答本文、セッションID、ホストのパスは含めていない。

## 手順と結果

数値の加算・乗算をレビューする小さな題材で、同じ担当のセッションを3回使った。
最初は小数の加算を壊し、次は加算を直して負数の乗算を壊し、最後に両方を直した。
その後、正しい候補を新規セッション2つで確認した。
全呼び出しは `/code-review` と `CLAUDE.local.md` の構成で、候補のハッシュは呼び出しの前後で不変だった。

| 呼び出し               | セッション | 判定       | API相当費用 | 所要時間 |
| ---------------------- | ---------- | ---------- | ----------: | -------: |
| 加算の不具合           | 新規       | 修正が必要 |   $0.064652 | 18.346秒 |
| 加算を修正、乗算に回帰 | 継続       | 修正が必要 |   $0.065391 | 16.064秒 |
| 両方を修正             | 継続       | 合格       |   $0.061086 | 13.048秒 |
| 最終確認 A             | 新規       | 合格       |   $0.060878 | 16.477秒 |
| 最終確認 B             | 新規       | 合格       |   $0.057131 | 16.258秒 |

継続3回の合計は $0.191129・47.458秒、新規の最終確認2回は追加で $0.118009・32.735秒だった。
全体では $0.309138・80.193秒。時間は直列で行った各呼び出しの合計で、factoryの並列実行時のwall timeではない。
同じ正しい候補に対する継続レビュー1回は、新規レビューより安くなっていない。
この結果から節約効果を主張できないため、既定値は変えない。

## 再現

ログイン済みのClaude CLIを使い、空の出力先を指定する。
最大5回、1回90秒、リトライなしで実行する。既存ディレクトリを指定すると拒否する。
開始済みの未確定呼び出しを再送するために、記録を消してやり直してはいけない。

```bash
pnpm exec tsx scripts/smoke-review-session.ts --run /tmp/review-session-smoke-new
```

実際のissueでフロー全体を比べる場合は、同じモデル・推論量・タスク・ベースcommitで、
`review.sessionMode` だけを `fresh` と `reuse-experiment` に変えて別のrunを作る。
`factory report` の `reviewCalls` で新規最終確認2回が含まれることを確認し、
`factory compare --run <fresh-run> --run <experiment-run>` で費用と時間を比較する。
両者が合格しただけで同じ検出品質とは判断せず、修正済み指摘の再報告、新しい回帰、最終確認だけが検出した指摘も確認する。

## 限界と失敗した試行

- 最初の試行は候補の絶対パスを指示に含めておらず、3回ともファイルを読めないというblockerになった。検証fixtureを直した上記の5回とは分け、検出実績には数えていない。
- 成功した試行ではAgentの起動は観測されなかった。失敗した試行では各回1件のAgent起動を観測したが、サブエージェントによる正しい候補のレビュー品質を示すものではない。部分ストリームとモデル別計測の回帰テストは別途行っている。
- プロジェクト内に置いた小さな `/code-review` コマンドであり、同名の他のプラグインの動作を保証しない。Bash、Web、MCPを必要とする構成は、このread-onlyレビュー環境では非対応。
- 題材は小さく、試行は1系列だけ。長い履歴、compaction、モデル変更、複雑な実変更の検出品質は未確認。
- 継続担当2人を含むfactory全体の実測比較ではない。factoryの2人分の分離、同じ固定候補、最終確認、修正後の無効化、失敗・未完了・上限はe2eテストで確認している。
- 費用は保存した単価によるAPI相当値で、契約の利用枠や請求額を表さない。

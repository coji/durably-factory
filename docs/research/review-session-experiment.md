# レビューセッション継続の検証記録

[トリアージ・仕様・レビュー・修正](../review-and-repair.md#再レビューのセッション継続reuse-experiment) に戻る。

この検証では、再レビュー時に同一セッションを継続する方式（`reuse-experiment`）が、毎回新規セッションでレビューする方式よりもコストが安くなるという結果は得られませんでした。

- **検証日**: 2026 年 11 月 11 日
- **環境**: Claude Opus 5.5（`effort: medium`）、Claude Code 2.1.321、Agent SDK 0.3.321
- **方法**: 通常の運用 DB やワーカーは使わず、別ディレクトリから Factory 本番と同じ呼び出し処理を実行。使用量・適用単価・CLI バージョンを [計測データ](review-session-smoke.json) に記録しています。

## 手順と実測結果

加算・乗算を行う小さな題材に対し、同一セッションで 3 回連続レビュー（加算にバグあり → 加算を直して乗算にリグレッション → 両方修正）を実施し、最後に修正済みの同一 Candidate を新規セッション 2 つで最終確認しました。すべての呼び出しで `/code-review` と `CLAUDE.local.md` を使用し、呼び出し前後で Candidate のハッシュが不変であることを確認しています。

| 呼び出し               | セッション | 判定       | API 換算費用 |  所要時間 |
| ---------------------- | ---------- | ---------- | -----------: | --------: |
| 加算の不具合           | 新規       | 修正が必要 |    $0.064652 | 18.346 秒 |
| 加算を修正、乗算に回帰 | 継続       | 修正が必要 |    $0.065391 | 16.064 秒 |
| 両方を修正             | 継続       | 合格       |    $0.061086 | 13.048 秒 |
| 最終確認 A             | 新規       | 合格       |    $0.060878 | 16.477 秒 |
| 最終確認 B             | 新規       | 合格       |    $0.057131 | 16.258 秒 |

- 初回＋継続 2 回の合計: `$0.191129`（47.458 秒）
- 最終確認 2 回の合計: `$0.118009`（32.735 秒）
- 全体合計: `$0.309138`（直列実行で 80.193 秒）

継続セッション 1 回あたりの費用も新規セッションより明確に下がっておらず、さらに最終確認の 2 回分が上乗せされるため、デフォルト設定（`"fresh"`）は変更していません。

## 再現方法

Claude にログインした状態で、未作成の出力ディレクトリを指定してスクリプトを実行します（最大 5 回、各回 90 秒上限）。

```bash
pnpm exec tsx scripts/smoke-review-session.ts --run /tmp/review-session-smoke-new
```

実リポジトリのタスクで比較する場合は、モデル・`effort`・タスク・ベースコミットを揃えたうえで `review.sessionMode` だけを `"fresh"` と `"reuse-experiment"` に切り替え、`pnpm factory report`（`reviewCalls` 欄）と `pnpm factory compare --runs FRESH_RUN,EXPERIMENT_RUN` で費用・時間・指摘内容の差を確認してください。

## 検証の限界と補足

- 初回の試行ではプロンプトに Candidate の絶対パスが含まれず 3 回ともファイルを読めなかったため、上の表はパス指定を修正した後の 5 回の結果です。
- 上記の成功した 5 回ではサブエージェント（`Agent`）の起動は観測されなかったため、主にレビュー担当本体のみの検出コストを表しています。
- 検証には専用の小さな `/code-review` コマンドを使用しており、長い会話履歴、コンテキスト圧縮（compaction）、実案件規模の複雑な差分での検出品質は未検証です。
- レビュアー 2 名の分離、修正後の旧判定無効化、最終確認の強制については Factory の E2E テストで検証済みですが、実運用で 2 名ともセッション継続した場合のコスト比較は実測していません。

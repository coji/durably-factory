# レビューセッション継続の検証結果

[見立て、レビュー、修正](../review-and-repair.md#再レビューのセッション継続実験) に戻る。

この試行では、セッションを継続したレビューの方が、新規セッションでのレビューより費用が少なくなることは確認できませんでした。

2026 年 11 月 11 日に、Claude Opus 5.5（推論量 `medium`）、Claude Code 2.1.321、Agent SDK 0.3.321 で検証しました。通常の実行とは別のディレクトリで、Factory と同じ呼び出し処理を使いました。
使用量、適用単価、CLI の版を保存しました。 [計測データ](review-session-smoke.json)

## 手順と結果

同じセッションで、加算に不具合がある版、加算を修正して乗算に不具合を加えた版、両方を直した版を順にレビューしました。最後の版は、新規セッション二つでも確認しました。すべての呼び出しで `/code-review` と `CLAUDE.local.md` を使い、前後で候補のハッシュが一致することを確かめました。

| 呼び出し               | セッション | 判定       | API相当費用 | 所要時間 |
| ---------------------- | ---------- | ---------- | ----------: | -------: |
| 加算の不具合           | 新規       | 修正が必要 |   $0.064652 | 18.346秒 |
| 加算を修正、乗算に回帰 | 継続       | 修正が必要 |   $0.065391 | 16.064秒 |
| 両方を修正             | 継続       | 合格       |   $0.061086 | 13.048秒 |
| 最終確認 A             | 新規       | 合格       |   $0.060878 | 16.477秒 |
| 最終確認 B             | 新規       | 合格       |   $0.057131 | 16.258秒 |

初回と継続 2 回で $0.191129、最終確認 2 回で $0.118009、計 $0.309138 でした。各呼び出しを順に実行した時間は計 80.193 秒です。費用はいずれも API 換算です。

## 再現

Claude にログインし、まだ存在しない出力ディレクトリを指定します。最大 5 回、各回 90 秒を上限に実行します。開始済みの呼び出しの結果が分からないときは、記録を残します。

```bash
pnpm exec tsx scripts/smoke-review-session.ts --run /tmp/review-session-smoke-new
```

実際のタスクで比べる場合は、モデル、推論量、タスク、ベースコミットをそろえ、`review.sessionMode` だけを `fresh` と `reuse-experiment` に変えます。`pnpm factory report` の `reviewCalls` で最終確認 2 回を確認し、`pnpm factory compare --runs FRESH_RUN,EXPERIMENT_RUN` で費用と時間を比べます。修正済みの指摘が再び出たか、新しい不具合を検出したか、最終確認で初めて出た指摘があったかも確認します。

## 限界と失敗した試行

- 最初の試行では候補の絶対パスが指示に含まれず、3 回ともファイルを読めませんでした。上の表は指示を直した後の 5 回です。
- サブエージェントの起動を確認できたのは、ファイルを読めなかった試行だけでした。この結果で評価できるのは、主にレビュー担当自身の検出です。
- 検証は専用の小さな `/code-review` コマンド 1 本で行いました。長い履歴、会話の圧縮、モデル変更、実案件での検出品質は未確認です。
- 二人のレビュアーを分ける動作や、修正後の判定の無効化、最終確認は Factory の E2E テストで確認しています。二人とも継続した場合の費用と時間は実測していません。

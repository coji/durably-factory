# 日々の操作

[README](../README.md) に戻る。

## 止まった実行と次の手順を見る

```bash
pnpm factory status
pnpm factory status --run RUN_ID
pnpm factory report --run RUN_ID
```

引数なしの `status` は、進行中、人の判断待ち、作業が止まったタスクを一覧にします。停止の理由と次の操作が分かります。`--format json` で機械処理用の出力に切り替えられます。実行ごとの詳細には `--run` を使います。

| 状況                                 | 操作                                                                                                         |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| 承認を待っている                     | `waits --run RUN_ID` で待ちの ID を確認し、`approve` または `reject` に `--run RUN_ID --wait WAIT_ID` を渡す |
| 最後の候補に追加修正が必要           | `repair --run RUN_ID` で候補を引き継ぐ                                                                       |
| 環境を直したので同じ候補を確かめたい | `recheck --run RUN_ID` で検査とレビューをやり直す                                                            |
| ベースの更新を取り込みたい           | `recheck --run RUN_ID --onto origin/main` で新しいベースの上で確かめる                                       |
| 入力から新しくやり直したい           | `retrigger --run RUN_ID`。現行の設定を読み直す場合は `--reload-config` を付ける                              |
| エージェントへの送信結果が分からない | [履歴と作業物を確認してから再開する](#スリープやワーカーの停止から再開する)                                  |

表のコマンドは `pnpm factory` に続けて実行します。各コマンドを使える停止理由は [レビューと修正](review-and-repair.md) を参照してください。

## 実行が止まるまで待つ（wait）

```bash
pnpm factory wait --run RUN_ID
pnpm factory wait --run RUN_ID --format json
```

実行が終わるか、人の判断が必要になるまで待ちます。判断を記録した後は、ワーカーが実行を再開するまで待ち続けます。

| 終了コード | 意味                                                     |
| ---------- | -------------------------------------------------------- |
| 0          | 承認・納品まで完了                                       |
| 1          | コマンドのエラー                                         |
| 2          | 人の判断などを待っている                                 |
| 3          | 失敗、却下、検査やレビューの上限などで納品に至らなかった |
| 4          | 取り消された                                             |
| 5          | `--timeout` に達した                                     |
| 6          | ワーカーの不在が `--worker-timeout` の間続いた           |

時間はミリ秒で指定します。全体の待ち時間は既定で無制限、ワーカー不在を待つ時間は既定で 10 秒です。`--no-worker-timeout` を付けると、ワーカーの不在だけでは打ち切りません。

## ワーカーの自動起動とアイドル終了

`trigger` や `approve` などで進められる仕事ができ、ワーカーがいなければ、CLI がバックグラウンドで起動します。ワーカーは仕事がなくなって既定で 30 秒たつと終了します。まだ判断されていない承認待ちは、進められる仕事に含みません。

```bash
pnpm factory worker
pnpm factory worker --exit-when-idle --idle-ms 10000
```

手動で起動したワーカーは、既定で動き続けます。自動起動を止めるには `--no-auto-worker` または `DURABLY_FACTORY_NO_AUTO_WORKER=1`。自動起動時のアイドル時間を変えるには `DURABLY_FACTORY_IDLE_MS` を使います。どちらのアイドル時間も 1 以上 2147483647 以下の整数のミリ秒です。

## ワーカーは状態のルートごとに 1 つだけ動く

ワーカーは保存先の `worker.lock` を SQLite でロックします。同じ保存先で二つ目を起動すると、稼働中の PID と起動元を表示して止まります。保存先が異なるワーカーは、それぞれ実行できます。

## ワーカーの稼働状態

`status` と `wait` はロックを見て、稼働中かどうかを判定します。PID は `worker.json` に記録されます。ロックが読めない場合は `unknown` と表示します。自動起動の PID とログの場所は標準エラー出力に表示され、ログは `logs/worker-YYYY-MM-DD.log` に追記されます。

## スリープやワーカーの停止から再開する

短いスリープからはそのまま続行します。リースが切れたりワーカーが落ちたりしたら、同じ保存先で `pnpm factory worker` を起動します。完了済みの工程は保存した結果を使い、途中だった固定検査をやり直します。リースは 10 分で、稼働中は 1 秒ごとに更新されます。

`uncertain-invocation` で止まった場合は、エージェントが依頼を受け取ったか確認します。

1. `pnpm factory report --run RUN_ID` で、対象の呼び出しを確認します。
2. プロバイダー側の履歴や作業ツリーを確認し、必要なら残っているエージェントのプロセスを止めます。
3. 稼働中のワーカーを停止します。PID は `status --run RUN_ID` で確認できます。
4. 送り直してよければ `pnpm factory resume --run RUN_ID --acknowledge-uncertain` を実行します。

再開は同じ run を使います。送信のやり直しは、作業や課金の重複につながる場合があります。

## 検査失敗の分類と自動再試行

| 分類      | ログで見つかった手がかり                       |
| --------- | ---------------------------------------------- |
| `timeout` | 検査の制限時間に達した                         |
| `setup`   | インストール、ビルド、モジュール解決などの失敗 |
| `test`    | テストやアサーションの失敗                     |
| `unknown` | 分類できる情報が足りない                       |

`timeout` と `setup` ではコード修正に進まず止まります。分類は手がかりなので、検査の標準出力・標準エラー出力を確認して次の操作を決めます。

プロバイダーが混雑やレート制限を明示した場合や、未確定の送信が残っていない未完了レビューは、保存済み入力で自動再試行できます。既定は系列ごとに 1 回で、`automaticRetryLimit` は 0〜3 を指定できます。一般の通信断などで送信結果が不明な場合は、人が確認して再開します。

## 止まった実行をアーカイブする

```bash
pnpm factory archive --run RUN_ID
pnpm factory archive --series ROOT_RUN_ID
pnpm factory unarchive --run RUN_ID
```

アーカイブした実行は対応が必要な一覧から外し、片付けられる作業ツリーを削除します。実行の記録はレポートで読めます。`--series` は、元の実行とその子のうち、アーカイブできる停止をまとめて扱います。ブランチも片付ける場合は `--delete-branch` を指定します。`unarchive` で一覧に戻せます。削除した作業ツリーやブランチは必要に応じて Git の操作で作り直します。

## 終わった実行の作業ツリーを片付ける

```bash
pnpm factory prune
pnpm factory prune --apply
pnpm factory prune --delete-branches --apply
```

最初に `prune` で対象を確認します。`--apply` で実際に片付けます。ログ、レポートに使う DB の記録、候補の差分や納品パッチは保存先に残ります。

## DB と作業物の置き場所

既定は `~/.local/state/durably-factory/` です。`DURABLY_FACTORY_STATE_DIR` を設定した場合は、CLI、UI、手動ワーカーに同じ値を渡します。

| 保存先からのパス                                            | 内容                                         |
| ----------------------------------------------------------- | -------------------------------------------- |
| `durably-factory.db`                                        | 実行、工程、試行、承認待ち                   |
| `worker.lock`、`worker.json`、`logs/`                       | ワーカーの状態とログ                         |
| `runs/RUN_ID/operation-checkpoints/`                        | エージェント呼び出しと検査のチェックポイント |
| `runs/RUN_ID/agent-logs/`、`runs/RUN_ID/verification-logs/` | エージェントと検査のログ                     |
| `runs/RUN_ID/candidates/`、`runs/RUN_ID/delivery/`          | 候補の差分、成果物                           |

テストやスモークテストでワーカーを起動するときは、普段とは別の `HOME` と専用の保存先を使います。

# Web UI

[README](../README.md) に戻る。

```bash
pnpm factory ui
pnpm factory ui --port 4500
```

起動後に表示される URL（デフォルト `http://127.0.0.1:4380/`）をブラウザで開きます。`127.0.0.1` のみで待ち受け、CLI と同じ SQLite DB を 3 秒ごとにポーリングします。`DURABLY_FACTORY_STATE_DIR` を変えている場合は、UI を起動するターミナルにも同じ環境変数を設定してください。

Web UI 自体はワーカーを起動しません。画面から承認や再実行を行ったあとに処理が進まない場合は、[ワーカーの稼働状態](operations.md#ワーカーのライフサイクル) を確認してください。

画面は「工場」「タスク」「振り返り」の 3 つと、実行ごとの詳細です。どの画面も、複数のリポジトリを扱っているときはリポジトリ単位で絞り込めます。タスクの一覧と実行の詳細の数字は CLI の `status`、`report`、`compare` と同じ計算から出しています。工場の図と振り返りの週ごとの図は `src/engine/flow.ts` の `flowOf` で集計していて、同じ数字を `compare --flow` で出せます([計測・レポート・比較](measurement.md#工場の流れを見るcompare---flow))。図の作り方は、デジタル庁「ダッシュボードデザインの実践ガイドブック」(2026-03-31 更新)に沿っています。

## 工場(`#/`)

開いて最初に見る画面です。全体から部分へ、次の順に並んでいます。

| 場所   | 表示される内容                                                                                                      |
| ------ | ------------------------------------------------------------------------------------------------------------------- |
| 左上   | 今週配送したタスクの数(前週と前 4 週の平均つき)、今週のリードタイムの中央値(前週つき)、判断待ちと止まったままの件数 |
| 右上   | いま工程(準備・仕様・実装・検証・レビュー・承認・配送)にあるタスクの数。最も多い工程をオレンジで示します            |
| 中段左 | 管理図: 直近 30 日に配送したタスクのリードタイムを終わった順に打ち、平均と上限を引きます                            |
| 中段右 | 止まった理由のパレート図: 理由ごとのタスク数を多い順に並べ、累積の割合を重ねます                                    |
| 下段左 | 1 タスクあたりの時間の内訳: 工程ごとの時間と待ち時間。最も長い工程をオレンジで示します                              |
| 下段右 | 判断が要るタスク: 判断待ちと止まったタスクを、理由とともに 5 件まで                                                 |

- スループットは、承認して配送したタスクの数で数えます。修正の実行は最初のタスクにまとめます。マージは工場の外の出来事で、記録していません。
- 管理図は X-Rs 管理図です。上の図(X)の上限は「平均 + 2.66 × 隣り合うタスクの差の平均」で、上限を超えたタスクは赤い三角で示し、押すとその実行を開きます。上限を超えたタスクが 2 件以上ある週には注記を付け、平均の同じ側に 9 点以上続いたところはオレンジの帯で示します。下の図(Rs)は隣り合うタスクの差で、上限(差の平均 × 3.267)を超えたところは、時間のかかり方が急に変わったところです。
- 集計は 30 秒ごと、ほかは 3 秒ごとに読み直します。直近 30 日のタスクが模擬(`fake`)のものだけのときは、模擬のタスクも含めて表示するボタンが出ます。このボタンは工場と振り返り(設定ごとの詳しい数字を含む)で共通で、ページを読み直すまで続きます。

## タスク(`#/tasks`)

| セクション     | 表示される内容                                                                         |
| -------------- | -------------------------------------------------------------------------------------- |
| 判断待ち       | 候補の承認や仕様の判断など、人のアクションを待っているタスク                           |
| 動いているもの | 実行中の工程と経過時間、順番待ち、ワーカー再開待ちのタスク                             |
| 止まったもの   | 停止理由と次に実行できる操作(不要になった停止はチェックボックスから一括アーカイブ可能) |
| 終わったタスク | 最終結果と親・子 run の履歴(「アーカイブ済みも表示」でアーカイブ済みタスクも閲覧可能)  |

- 各操作ボタンの下にある「同じ操作の CLI コマンド」を開くと、同等の操作を行う CLI コマンドをコピーできます。画面からの再実行は保存済みの入力を使うため、`factory.json` を読み直したい場合は CLI の `retrigger --reload-config` を使ってください。

## 振り返り(`#/review`)

週ごとに、工場が速くなったか、どこに時間と利用枠を使ったかを見る画面です(以前の `#/compare` も開けます)。

- **週ごとの図**: 配送数(却下と停止を積み上げ)、リードタイム(中央値と最小〜最大)、プロバイダー別のトークン、工程の手戻り(2 回以上入ったタスクの割合)、1 タスクあたりの時間の内訳。
- **設定ごとの詳しい数字**: 「週ごとの推移」(`compare --trend` 相当)と「設定ごとの比較」(`compare --runs` 相当)を切り替えられます。集計の仕様は [計測・レポート・比較](measurement.md) と同じです。

## 実行の詳細(`#/runs/RUN_ID`)

タスク名や各 run を開くと、上から順に、いまの状況と次の操作、レビューの要点、時間と費用、工程の時系列、記録の詳細(閉じた状態)を確認できます。数字はそれぞれ 1 か所にだけ出します。

- **いまの状況**: どうなったか、人が確認すること、次の操作。同じ操作の CLI コマンドと作業ツリーを片付けるコマンドは、閉じた欄に入っています。工程の並び(準備 › 事前確認 › …)は、まだ先の工程が残っている実行にだけ出します。
- **時間と費用**: 工程(準備・仕様・実装・検証・レビュー・承認・配送)と待ち時間ごとに、この実行の時間を棒で、直近 30 日の 1 タスク平均を縦線で重ね、作業時間と費用を並べます。最後の行はリードタイムで、配送したタスクの平均と並べ、管理図の上限を超えたら赤で示します。合計トークンと修正の回数は表の下に出します。
- 時系列の行を選択すると、エージェントの出力や `check` の stdout/stderr ログをリアルタイムで追跡できます(長いログは末尾 256 KiB を表示するため、全文は表示されたパスをコピーして確認してください)。

## デモデータと UI コンポーネント確認

DB やワーカーを用意せず UI の見た目だけ確認したい場合は、`http://127.0.0.1:4380/#/design` を開きます。実際の運用に近いデータで画面と操作を試したい場合は、`seed` コマンドで一時ディレクトリにデモ環境を構築できます。

```bash
pnpm factory seed
pnpm factory seed --home ~/tmp/factory-demo --latency 3000-15000
```

`seed` は普段の `~/.local/state/durably-factory/` に一切触れず、一時ディレクトリ（`--home` 指定時は空または未作成のパス）にサンプルリポジトリと複数の `fake` 実行データを作成します。完了後、その環境用の `ui` 起動コマンドとワーカー情報が表示されます（`--latency` は seed の間に終わる run の、1 回の模擬呼び出しにかかる時間範囲をミリ秒で指定します。動き続ける run の呼び出しは 10〜20 分かかります）。
